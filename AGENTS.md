# Agent instructions

These rules apply to all AI agents that work in this project. Apply them to all responses, reports, edits, and new files.

## No em dashes

- Never use the em dash character (Unicode U+2014) in a response.
- Never add an em dash to application text or copy. This includes visible text, labels, messages, and text stored in source files, templates, or content files.
- When you edit existing application copy, replace any em dash in that copy with a period, comma, colon, or parentheses. Keep the meaning clear.

## Concise reports

- Keep reports to the user extremely short.
- Give the result first. Include only facts needed to understand the result, a failure, or a required decision.
- Omit filler, repeated facts, and unnecessary grammar when the meaning stays clear.

## ASD-STE100

- Strictly follow ASD-STE100 Simplified Technical English for responses and application text or copy.
- Use approved words with their approved meanings. Use permitted technical names and technical verbs only as allowed by ASD-STE100.
- Use specific words. Avoid vague terms, idioms, jargon, and words with more than one possible meaning in context.
- Use short sentences, active voice, and one instruction per sentence.
- Use the same term for the same thing throughout the project.
- Keep the meaning clear when you shorten text. ASD-STE100 clarity takes priority over brevity.
- Do not claim verified ASD-STE100 compliance unless you checked the text against the standard and its approved dictionary. If those references are unavailable, state that limit when a compliance check is requested.
